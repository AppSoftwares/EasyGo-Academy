REGLA DE ORO PARA FECHAS Y ZONAS HORARIAS:
  • SIEMPRE guardar en UTC en la base de datos (campo timestamp WITH TIME ZONE)
  • NUNCA guardar offsets como "UTC-5" o "UTC+1"
  • La zona horaria del usuario se guarda en su perfil como IANA string:
    Ejemplos CORRECTOS: "America/New_York", "America/Los_Angeles", "Europe/Madrid"
    Ejemplos INCORRECTOS: "-05:00", "EST", "UTC-5"
  • Convertir a zona local SOLO en la capa de presentación (UI)
  • Usar la librería date-fns-tz o Temporal API para conversiones

REGLAS DE PERFORMANCE EN BD:
  1. ÍNDICES OBLIGATORIOS en todos los campos de búsqueda y filtro
  2. Sin consultas sin índice (usar EXPLAIN ANALYZE para verificar)
  3. Sin procesos que bloqueen la BD (usar transacciones cortas)
  4. Paginación siempre con LIMIT + OFFSET o cursor-based
  5. Soft delete: columna deleted_at TIMESTAMP (no DELETE físico)

-- Trigger para auditoría automática en tablas críticas
CREATE OR REPLACE FUNCTION log_audit_change()
RETURNS TRIGGER AS $$
BEGIN
  INSERT INTO audit_logs(action, table_name, record_id, old_values, new_values)
  VALUES (TG_OP, TG_TABLE_NAME, NEW.id,
          row_to_json(OLD)::JSONB, row_to_json(NEW)::JSONB);
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

  • Errores de BD: capturar, loggear en Sentry, mostrar mensaje genérico al usuario

SYNC OFFLINE→ONLINE:
  1. Acción del usuario → guardar en IndexedDB (pending_sync store)
  2. Si hay conexión: intentar sync inmediato
  3. Si no hay conexión: mostrar indicator "Sin conexión — guardado localmente"
  4. Al recuperar conexión: sync automático silencioso
  5. Conflictos: last-write-wins por timestamp
  6. Máximo 3 reintentos con backoff exponencial

INDICADOR DE ESTADO:
  🟢 Sincronizado | 🟡 Pendiente (X cambios) | 🔴 Error de sync
